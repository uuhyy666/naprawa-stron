Problem numer jeden: klucz do modelu w kodzie aplikacji

PWA to aplikacja, która w całości działa w przeglądarce użytkownika. Wszystko, co jest w jej kodzie, jest jawne — łącznie z kluczem do modelu AI, jeśli ktoś go tam wpisze. Nie chroni przed tym minifikacja, zmienna środowiskowa wstrzyknięta przy budowaniu ani schowanie klucza „głębiej w kodzie”.

Konsekwencja jest finansowa, nie teoretyczna: znaleziony klucz ktoś podepnie pod własne zapytania, a rachunek przyjdzie do organizacji. Przy projekcie NGO jest to szczególnie dotkliwe, bo budżet jest z darowizn.

Narzędzie: sprawdź w 10 sekund, czy kod wystawia klucz

Wklej zawartość pliku JavaScript swojej aplikacji (albo fragment kodu). Wszystko liczy się w Twojej przeglądarce — nic stąd nie wychodzi na żaden serwer.

Rozwiązanie: pośrednik po stronie serwera

Aplikacja nie rozmawia z modelem bezpośrednio. Rozmawia z własnym punktem końcowym, który dopiero on zna klucz. Klucz nigdy nie opuszcza serwera. Przy okazji zyskujesz trzy rzeczy, których bez pośrednika nie da się mieć wcale:

  • Limit zapytań — jeden użytkownik nie wyczerpie budżetu całej organizacji.
  • Twardy limit kosztów — po przekroczeniu miesięcznego progu pośrednik przestaje przepuszczać zapytania, zamiast generować rachunek.
  • Kontrola źródła — zapytania przyjmowane tylko z Twoich domen, więc cudza strona nie użyje Twojego modelu.

Gotowy kod pośrednika (Cloudflare Worker — darmowy plan wystarcza)

// Pośrednik między aplikacją PWA a modelem AI.
// Klucz siedzi w zmiennej środowiskowej Workera i NIGDY nie trafia do przeglądarki.
// Wymaga jednego powiązania KV o nazwie LICZNIK (do limitów i kosztów).

const DOZWOLONE_ZRODLA = ['https://twoja-domena.pl', 'https://klient1.twoja-domena.pl'];
const LIMIT_NA_UZYTKOWNIKA_DZIENNIE = 50;
const LIMIT_KOSZTU_MIESIAC_USD = 20;

export default {
  async fetch(zadanie, env) {
    const zrodlo = zadanie.headers.get('Origin') || '';
    if (!DOZWOLONE_ZRODLA.includes(zrodlo)) {
      return odpowiedz({ blad: 'Niedozwolone źródło' }, 403, zrodlo);
    }
    if (zadanie.method === 'OPTIONS') return odpowiedz(null, 204, zrodlo);

    // Limit na użytkownika — klucz oparty o adres IP i dzień.
    const ip = zadanie.headers.get('CF-Connecting-IP') || 'nieznane';
    const dzien = new Date().toISOString().slice(0, 10);
    const kluczLicznika = `uzycie:${ip}:${dzien}`;
    const uzyte = Number(await env.LICZNIK.get(kluczLicznika)) || 0;
    if (uzyte >= LIMIT_NA_UZYTKOWNIKA_DZIENNIE) {
      return odpowiedz({ blad: 'Dzienny limit zapytań wyczerpany' }, 429, zrodlo);
    }

    // Twardy limit kosztów całej instalacji — to on ratuje budżet NGO.
    const miesiac = dzien.slice(0, 7);
    const koszt = Number(await env.LICZNIK.get(`koszt:${miesiac}`)) || 0;
    if (koszt >= LIMIT_KOSZTU_MIESIAC_USD) {
      return odpowiedz({ blad: 'Miesięczny limit kosztów osiągnięty' }, 429, zrodlo);
    }

    const dane = await zadanie.json();
    const odp = await fetch('https://api.anthropic.com/v1/messages', {
      method: 'POST',
      headers: {
        'content-type': 'application/json',
        'x-api-key': env.KLUCZ_API,        // ← klucz tylko tutaj, po stronie serwera
        'anthropic-version': '2023-06-01'
      },
      body: JSON.stringify({
        model: 'claude-sonnet-5',
        max_tokens: 1024,
        messages: dane.messages          // przekazujemy tylko to, co potrzebne
      })
    });

    const wynik = await odp.json();
    const zuzycie = wynik.usage || {};
    const przyrost = szacunkowyKoszt(zuzycie);
    // Liczniki aktualizujemy PO udanym zapytaniu, żeby błąd modelu nie zjadał limitu użytkownika.
    await env.LICZNIK.put(kluczLicznika, String(uzyte + 1), { expirationTtl: 172800 });
    await env.LICZNIK.put(`koszt:${miesiac}`, String(koszt + przyrost));

    return odpowiedz(wynik, odp.status, zrodlo);
  }
};

function szacunkowyKoszt(u) {
  // Stawki wpisujemy jawnie i w jednym miejscu — żeby dało się je poprawić,
  // gdy cennik się zmieni, zamiast szukać mnożników po całym kodzie.
  const zaMlnWejscie = 3, zaMlnWyjscie = 15;
  return ((u.input_tokens || 0) * zaMlnWejscie + (u.output_tokens || 0) * zaMlnWyjscie) / 1e6;
}

function odpowiedz(dane, status, zrodlo) {
  return new Response(dane ? JSON.stringify(dane) : null, {
    status,
    headers: {
      'content-type': 'application/json',
      'Access-Control-Allow-Origin': zrodlo,
      'Access-Control-Allow-Headers': 'content-type'
    }
  });
}

Problem numer dwa: ta sama aplikacja wdrażana dziesięć razy

W opisie zlecenia jest zdanie: „instalujemy ją 10 razy, czyli ten sam produkt — 10 razy, dla klientów testowych”. To miejsce, w którym projekt albo zostanie utrzymywalny, albo zamieni się w dziesięć osobnych aplikacji, których nikt już nie ogarnie.

W praktyce: jedno repozytorium, a różnice między klientami (nazwa, logo, kolory, treści, adres pośrednika AI) siedzą w pliku konfiguracyjnym wczytywanym przy starcie — /config.json osobny dla każdej instalacji. Personalizacja, którą przygotowuje zleceniodawca, sprowadza się wtedy do wypełnienia jednego pliku, bez dotykania kodu.

Skutek praktyczny: dziesiąta instalacja zajmuje kilkanaście minut zamiast całego dnia, a poprawka bezpieczeństwa dociera do wszystkich dziesięciu tego samego popołudnia. Przy aplikacji finansowanej z darowizn to jest różnica między projektem, który da się utrzymać, a takim, który po roku trzeba pisać od nowa.

Czego tu nie ma i czego nie wiem

  • Nie widziałem tej aplikacji — działam na podstawie opisu zlecenia. Powyższe to wzorce, nie diagnoza konkretnego kodu. Po podpisaniu NDA i zajrzeniu do repozytorium część rzeczy na pewno okaże się inna.
  • Nie znam docelowego hostingu. Kod pośrednika pokazałem na Cloudflare Workers, bo darmowy plan wystarcza na start i nie wymaga utrzymywania serwera. Na zwykłym hostingu z PHP robi się to samo, tylko inaczej.
  • Nie znam skali ruchu ani modelu, więc podane limity (50 zapytań na osobę dziennie, 20 USD miesięcznie) to wartości przykładowe do ustalenia, a nie rekomendacja.
  • Narzędzie wyżej nie jest audytem bezpieczeństwa. Szuka wzorców wyglądających jak klucze i zwraca uwagę na typowe błędy. Brak trafień nie znaczy „bezpieczne” — znaczy tylko, że tych konkretnych wzorców nie ma.
